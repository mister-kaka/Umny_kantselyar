# Система логирования

## Общая информация

Логирование в проекте разделено на два уровня:
- логирование для разработчиков - запись всех запросов к API в файлы логов
- логирование для пользователей - запись действий в журнал аудита (таблица audit_log)

## Логирование для разработчиков

Реализовано через модуль Logger (AppLoggerService).

### Где хранятся логи

Логи записываются в папку backend/logs/.
Файлы создаются по дням: logs-YYYY-MM-DD.json.
Пример: logs-2026-06-15.json.

### Формат записи

Каждая запись содержит поля:
- timestamp - время события в московском часовом поясе (Europe/Moscow)
- module - название модуля, в котором произошло событие (Auth, Documents, Settings, Notifications, Admin и другие)
- type - тип HTTP-запроса (GET, POST, PUT, DELETE, PATCH)
- url - URL эндпоинта
- action - описание действия на русском языке
- status - статус выполнения (success или error)
- statusCode - HTTP-статус ответа (200, 201, 400, 404, 500 и другие)
- message - дополнительное сообщение

### Пример записи

{
  "timestamp": "2026-06-15T12:30:00.000+03:00",
  "module": "Documents",
  "type": "POST",
  "url": "/documents/upload",
  "action": "загрузка документа",
  "status": "success",
  "statusCode": 201,
  "message": "Файл dogovor.pdf загружен (id: 35)"
}

### Какие события логируются

Логируются все запросы ко всем эндпоинтам:
- вход в систему (успешный и неуспешный)
- получение данных дашборда
- все операции с документами (список, карточка, загрузка, извлечение текста, AI-анализ, проверка, маршрутизация, отклонение, редактирование, удаление)
- все операции со справочниками (типы, категории, отделы)
- все настройки (AI, интерфейс, уведомления)
- экспорт и импорт данных
- уведомления (получение, отметка прочитанными, удаление)
- безопасность (сессии, история входов, аудит-лог)
- администрирование (управление пользователями, системные настройки, очистка данных, бэкап, статистика, рассылка)

### Безопасность логов

- Пароли не записываются в логи
- JWT-токены не записываются в логи
- API-ключи AI-провайдера не записываются в логи в открытом виде

### Просмотр логов

Логи можно просмотреть:
- в папке backend/logs/ - открыть соответствующий JSON-файл
- через интерфейс: Администрирование - Система - Логи сервера (скачать за сегодня или за период)
- через команду docker logs umny_kan_postgres - для логов базы данных

## Логирование для пользователей

Реализовано через модуль AuditLog (AuditLogService).
Записи сохраняются в таблицу audit_log.
Просмотр доступен в интерфейсе:
- Настройки - Безопасность - Журнал действий (только свои действия)
- Администрирование - Журнал (действия всех пользователей с фильтрами)

### Какие действия записываются

Действия с пользователями:
- login - вход в систему
- logout_all - выход со всех устройств
- logout_session - завершение конкретной сессии
- profile_update - обновление профиля
- password_change - смена пароля
- avatar_upload - загрузка аватара
- user_created - создание пользователя
- user_deleted - удаление пользователя
- user_role_change - смена роли
- user_blocked - блокировка пользователя
- user_unblocked - разблокировка пользователя
- user_password_reset - сброс пароля

Действия с документами:
- document_upload - загрузка документа
- document_delete - удаление документа
- document_update - редактирование документа
- document_verify - проверка документа
- document_route - маршрутизация документа
- document_reject - отклонение документа
- ocr_extract - извлечение текста
- ai_analysis - AI-анализ
- ai_analysis_error - ошибка AI-анализа

Действия с данными:
- export_excel - экспорт в Excel
- export_data - экспорт данных
- import_data - импорт данных

Действия с настройками:
- settings_update_ai - изменение настроек AI
- settings_update_interface - изменение интерфейса
- settings_update_notifications - изменение уведомлений
- system_settings_update - изменение системных настроек
- cleanup - очистка данных

Действия с уведомлениями:
- notification_mark_read - отметка уведомления прочитанным
- notification_mark_all_read - отметка всех уведомлений прочитанными
- notification_delete - удаление уведомления
- notification_delete_all_read - удаление всех прочитанных
- mass_notification - массовая рассылка

Действия со справочниками и комментариями:
- comment_added - добавление комментария
- comment_deleted - удаление комментария
- reference_created - создание элемента справочника
- reference_deleted - удаление элемента справочника

## Очистка логов

Логи разработчика хранятся в файлах и не очищаются автоматически.
При необходимости старые файлы можно удалить вручную из папки backend/logs/.

Записи аудита пользователей хранятся в базе данных.
Очистка доступна через интерфейс:
- Администрирование - Система - Очистка данных (удалить записи старше N месяцев)
- Настройки - Безопасность - Журнал действий (кнопка «Очистить журнал»)
