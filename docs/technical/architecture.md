# Архитектура системы

## Стек технологий

1. Бэкенд - NestJS, TypeScript, TypeORM, PostgreSQL, JWT, bcrypt, class-validator, HttpModule, Multer, pdf-parse, mammoth, xlsx, tesseract.js, sharp, exceljs
2. Фронтенд - React, TypeScript, Vite, React Router, Axios, recharts, mammoth, xlsx
3. База данных - PostgreSQL с расширением pgvector (запускается в Docker)
4. Стили - CSS, CSS-переменные, адаптивная вёрстка

## Структура проекта

Проект состоит из трёх частей - бэкенд (NestJS), фронтенд (React + Vite) и база данных (PostgreSQL в Docker).

### Бэкенд

Бэкенд расположен в папке backend/ и построен по модульной архитектуре NestJS. Каждый модуль находится в собственной папке и содержит контроллер, сервис, DTO и при необходимости дополнительные утилиты.

В корне backend/src/ находятся - main.ts (точка входа), app.module.ts (главный модуль с подключением TypeORM и Multer), app.controller.ts и app.service.ts (тестовые эндпоинты для проверки работоспособности).

Папки модулей - auth/, dashboard/, documents/ (с подмодулями list/, crud/, extraction/, routing/, search/), departments/, document-types/, document-categories/, ai/, settings/, notifications/, security/, analytics/, image-processor/, logger/, audit/.

Папка entities/ содержит TypeORM-сущности для всех таблиц базы данных (22 файла). Папка db/ содержит seed.sql с тестовыми данными для инициализации базы. Папка types/ содержит типизацию Express.Multer.File. Папка utils/ содержит утилиты - transliterate.ts (транслитерация русских названий в латиницу для кодов). В папке модуля AI находится ai-key.util.ts (шифрование, дешифрование и маскировка API-ключа). Папка uploads/ содержит загруженные файлы документов и аватары пользователей. Папка logs/ содержит файлы логов по дням (logs-YYYY-MM-DD.json).

### Модули бэкенда

- Auth - авторизация. Использует JWT-токены с истечением срока. Пароли хэшируются через bcrypt. При входе создаётся сессия в таблице user_sessions и запись в login_history. Поддерживается профиль пользователя (GET/PUT), загрузка аватара, смена пароля.

- Dashboard - главная страница. Возвращает общую статистику (всего документов, в обработке, требуют проверки, направлено в отдел), последние документы и статусы маршрутов по отделам. Отделы фильтруются по is_active - архивные не отображаются.

- Documents - основной модуль для работы с документами. Включает подмодули - list (список с фильтрами и пагинацией), crud (загрузка, удаление, обновление, верификация, маршрутизация, отклонение, комментарии), extraction (извлечение текста), routing (маршрутизация и шаблоны), search (поиск по документам и AI-поиск), export (экспорт в Excel).

- Departments - справочник подразделений. Поддерживает создание, архивацию (мягкое удаление через is_active), восстановление, детальную статистику по отделу (количество документов, сотрудники, график поступлений по месяцам с фильтрацией по датам). При архивации отдел скрывается из списков, AI перестаёт его предлагать.

- DocumentTypes и DocumentCategories - справочники типов и категорий. Поддерживают создание и удаление. При удалении проверяется наличие связанных документов. При создании нового типа или категории через AI, они автоматически добавляются в справочник.

- AI - анализ документов через DeepSeek API. Промпт формируется динамически на основе актуальных справочников (типы, категории, отделы - только активные). API-ключ хранится в зашифрованном виде (AES-256-CBC). Поддерживается мок-режим для тестирования.

- Settings - настройки системы. Управление AI-провайдером, настройки уведомлений (16 типов с разделением на документы и систему), настройки интерфейса (компактный вид, показ уверенности, лимит страниц, тема), экспорт и импорт данных в JSON.

- Notifications - уведомления пользователей. Поддерживает создание уведомлений 16 типов, WebSocket-обновление счётчика непрочитанных в реальном времени, отметку прочитанными, удаление. Уведомления об одном документе объединяются (upsert).

- Security - безопасность. Управление сессиями (просмотр, завершение конкретной, выход со всех устройств), история входов с пагинацией, журнал действий (аудит-лог) с пагинацией и фильтрацией по действию и документу.

- Analytics - аналитика. Возвращает общую статистику системы - всего документов, средняя уверенность, количество отклонённых, за последние 7 дней, требуют проверки, обработано AI. Используется на странице аналитики.

- ImageProcessor - обработка изображений. Использует sharp для предобработки изображений перед OCR - авто-поворот, изменение размера (до 2500x3500), перевод в оттенки серого, нормализация контрастности. Вызывается из модуля Documents при извлечении текста из изображений. При ошибке обработки возвращает исходный файл.

- Logger - система логирования. Реализован через AppLoggerService. Все запросы логируются в папку backend/logs/ в файлы по дням (logs-YYYY-MM-DD.json). Каждая запись содержит - время (московское), модуль, тип запроса, URL, действие, статус, код и сообщение. Пароли и токены в логах скрыты.

- AuditLog - журнал действий пользователей. Отдельный модуль, предоставляющий сервис для записи всех значимых действий в таблицу audit_log. Используется модулями Auth, Documents, Settings, Notifications, Security. Записи включают - пользователя, действие, ID документа, детали. Просмотр через Security модуль с пагинацией и фильтрацией.

### Фронтенд

Фронтенд расположен в папке frontend/ и построен на React с Vite.

- В корне frontend/src/ находятся - index.tsx (точка входа React), App.tsx (корневой компонент с маршрутизацией), declarations.d.ts и vite-env.d.ts (объявления типов для Vite).

- Папка pages/ содержит страницы, не входящие в дашборд - LoginPage, DashboardPage, DocumentCardPage, DepartmentDetailPage, ProfilePage.

- Папка components/ содержит переиспользуемые компоненты (Card, Table, Sidebar, Header, DropdownButton, Pagination, Tooltip, Search, Scanner, ScrollToTop) и подстраницы дашборда в components/SubPages/ (MainMenu, DocumentsListPage, Verification, Routing, Departments, Notifications, UploadPage, Analytics, Settings).

- Папка contexts/ содержит контексты приложения - SidebarContext (состояние сворачивания сайдбара), SettingsContext (настройки интерфейса - компактный вид, показ уверенности, лимит страниц, тема).

- Папка constants/ содержит константы - statuses.ts (справочник статусов документов с переводом на русский язык и цветовыми классами).

- Папка services/ содержит API-сервис api.ts (axios с перехватчиками для JWT-токенов и все функции обращения к бэкенду).

- Папка types/ содержит TypeScript-интерфейсы для всех сущностей, запросов и ответов (index.ts).

- Папка utils/ содержит утилиты - moscowTime.ts (конвертация дат в московское время), getThemedIcon.ts (подстановка _dark-иконок в тёмной теме).

- Папка styles/ содержит CSS-файлы для каждой страницы и компонента, а также global.css с переменными и базовыми стилями.

- В корне frontend/ находится папка public/ со статическими файлами - иконки (sidebar, header, dashboard, filters, common, upload, routing, departments, notifications, analytics), логотип, favicon.

### Компоненты фронтенда

- Sidebar - боковое меню. Поддерживает сворачивание, навигацию по разделам, иконки с тёмной темой. Динамически отображает версию приложения из API.

- Header - верхняя панель. Поиск документов с выпадающим меню, кнопка сканирования, дропдаун уведомлений с бейджем счётчика (обновляется через WebSocket), меню профиля.

- Card - универсальная карточка для статистики и контента. Единый стиль - border-top акцентного цвета, ховер с поднятием, иконка 48px, значение 24px, подпись 13px капсом.

- Table - универсальная таблица с пагинацией. Единые стили - строки 48px, шапка с серым текстом, ховер строк.

- DropdownButton - выпадающий список для фильтров. Поддерживает иконки, активный элемент, анимацию, тёмную тему.

- Pagination - пагинация. Кнопки «Назад» и «Вперёд», отображение текущей страницы.

- Tooltip - тултип. Позиционирование сверху или снизу, адаптация под тёмную тему.

- Search - поиск по документам. Задержка 400мс, выпадающее меню, закрытие по клику вне.

- Scanner - сканирование документов с камеры. Открывается в модальном окне поверх страницы загрузки. Использует getUserMedia для доступа к камере, предпочтительно задней (facingMode - environment). Захватывает кадр через canvas, конвертирует в JPEG, отправляет на POST /documents/upload. После успешной загрузки сохраняет данные скана в localStorage, закрывает модальное окно и перенаправляет на страницу загрузки, где файл автоматически добавляется в очередь обработки. Поддерживает обработку ошибок - доступ запрещён, камера не найдена, ошибка отправки.

- ScrollToTop - кнопка «Вверх». Появляется при прокрутке страницы более чем на 400px. При клике плавно прокручивает страницу к началу.

- ProtectedRoute - защита маршрутов. Проверяет наличие JWT-токена в localStorage или sessionStorage. Если токен отсутствует, перенаправляет на страницу входа.

### Подстраницы дашборда (SubPages)

- MainMenu - главная страница дашборда. Карточки статистики (всего документов, направлено в отдел, ожидают проверки), таблица последних документов, блок статусов маршрутов по отделам с группировкой. Отделы фильтруются по is_active - архивные не отображаются.

- DocumentsListPage - архив документов. Таблица с колонками - рег. номер, название, отправитель, дата загрузки, тип, категория, статус, отдел. Фильтры по дате, типу, категории, статусу. Пагинация с выбором количества на странице. Массовое удаление выбранных документов. Экспорт в Excel. Чекбоксы для выбора строк.

- Verification - очередь проверки. Таблица документов со статусом pending_verification. Колонки - рег. номер, название, дата загрузки, тип (AI), уверенность (скрывается через настройку showConfidence), статус. Кнопка «Взять в проверку» открывает карточку документа на вкладке «Проверка».

- Routing - контроль маршрутизации. Единая таблица всех направленных документов с цветовой индикацией - зелёная полоска (совпадение AI и оператора), красная (расхождение). Колонки - рег. номер, название, дата, рекомендован (AI), направлен, статус, оператор, комментарий. Кнопка перехода в отдел. Фильтры по типу совпадения, отделу, оператору. Пагинация с выбором количества.

- Departments - подразделения. Карточки отделов с иконкой, названием, количеством документов, шкалой загруженности (зелёный, жёлтый, красный), последним документом. Сортировка по названию или загруженности. Фильтр «Активные» и «Архивные». Модалки добавления, архивации и восстановления. Тултипы на кнопках и шкале.

- Notifications - уведомления. Карточки статистики по типам уведомлений (непрочитанные, требуют проверки, низкая уверенность, ошибки). Группировка по датам или по документам с таймлайном событий. Фильтры по типу, дате, статусу прочтения. Пагинация с выбором количества. Массовое удаление. Бесконечная подгрузка при скролле.

- UploadPage - загрузка документов. Drag-and-drop зона с информацией о поддерживаемых форматах и лимитах. Очередь файлов с возможностью перетаскивания для изменения порядка. Три шага обработки - загрузка, извлечение текста, AI-анализ. Прогресс-бар. Массовая загрузка до 15 файлов одновременно. Предпросмотр файлов. Кнопка «Приступить к проверке» после успешной загрузки.

- Analytics - аналитика. Шесть карточек статистики. Круговая диаграмма по типам документов, горизонтальная столбчатая по категориям, линейный график динамики поступлений за 14 дней, столбчатая диаграмма по статусам. Графики адаптируются под тёмную тему.

- Settings - настройки системы. Восемь вкладок - Провайдер (AI), Интерфейс (тема, компактный вид, лимит страниц), Уведомления (16 переключателей в две колонки), Безопасность (сессии, история входов, аудит-лог с аватарами и пагинацией), Справочники (типы, категории, отделы), Правила маршрутизации (создание и удаление шаблонов), Резервное копирование (экспорт и импорт JSON), О системе (версия, технологии, команда). Вкладки в стиле карточки документа.

## Поток обработки документа

1. Загрузка. Пользователь загружает файл через страницу загрузки (UploadPage) или сканирует с камеры (Scanner). Сканнер захватывает кадр с камеры, отправляет файл на POST /documents/upload, сохраняет данные в localStorage и перенаправляет на страницу загрузки, где файл автоматически добавляется в очередь. Бэкенд сохраняет файл в uploads/documents/{id}/, создаёт запись в таблице documents, генерирует регистрационный номер вида ВХ-2026-XXX. Возвращает ID документа.

2. Извлечение текста. Фронтенд вызывает POST /documents/:id/extract-text. Бэкенд определяет формат файла и извлекает текст - PDF через pdf-parse, DOCX через mammoth, XLSX через xlsx, изображения (JPG, PNG, TIFF) проходят предобработку через ImageProcessor (авто-поворот, изменение размера до 2500x3500, перевод в оттенки серого, нормализация контрастности) и затем распознаются через tesseract.js, TXT читается напрямую. Результат сохраняется в таблицу ocr_results.

3. AI-анализ. Фронтенд вызывает POST /documents/:id/analyze-ai. Бэкенд отправляет извлечённый текст в DeepSeek API с промптом, содержащим список доступных типов, категорий и отделов из базы данных (только активные). AI возвращает предложенные тип, категорию, отдел, сводку, дату, сумму, контрагента, ключевые фразы и источник. Результат сохраняется в document_ai_results. Документу присваивается статус pending_verification. Уверенность рассчитывается как OCR (20 процентов) плюс AI-анализ (80 процентов).

4. Проверка оператором. Оператор открывает карточку документа на вкладке «Проверка». Видит предложенные AI тип, категорию и отдел с процентами уверенности. Может скорректировать данные, выбрать отдел вручную или применить правило маршрутизации. Нажимает «Подтвердить» (PUT /documents/:id/verify) — статус меняется на verified. Затем «Направить в отдел» (POST /documents/:id/route) — создаётся запись в document_routes, статус меняется на routed.

5. Маршрутизация. На странице «Контроль маршрутизации» (GET /documents/routing) отображаются все направленные документы с цветовой индикацией - зелёный (AI и оператор совпали), красный (разошлись). Можно фильтровать по отделу, оператору, типу совпадения.

## Единый стиль

Все страницы используют единые CSS-переменные, заданные в global.css. Цветовая палитра построена вокруг бирюзового акцента. Статусы имеют собственную цветовую схему с использованием полупрозрачных фонов. Адаптив выполнен по пяти брейкпоинтам - 1024px, 768px, 480px, 375px, 320px. На мобильных устройствах кнопки не менее 44px высотой, добавлены touch-состояния. Поддерживается тёмная тема через data-theme="dark" с полным набором переменных.

Карточки статистики на всех страницах имеют единый стиль - border-top 3px акцентного цвета, иконка 48px, значение 24px жирным, подпись 13px капсом, ховер с поднятием на 2px и тенью.

Таблицы имеют единый стиль - высота строк 48px, шапка с серым текстом 13px, ховер строк с лёгким фоном, горизонтальный скролл на мобильных.

Заголовки страниц - 24px, жирность 600, цвет text-primary. Подзаголовки - 14px, цвет text-tertiary.

## Поддерживаемые форматы файлов

1. Документы - PDF (текстовые и сканы), DOCX (Microsoft Word), TXT (текстовые файлы), XLSX (Microsoft Excel)
2. Изображения - JPG, JPEG, PNG, TIFF (сканы и фотографии)

Максимальный размер файла - 50 МБ
Максимум файлов за одну загрузку - 15

## База данных

25 таблиц: roles, users, departments, document_types, document_categories, documents, document_routes, document_sources, document_files, ocr_results, document_classifications, ai_settings, document_ai_results, user_notification_settings, user_interface_settings, login_history, route_templates, document_comments, audit_log, notifications, user_sessions, search_synonyms, search_log, system_settings

Связи:
- пользователь имеет роль (ManyToOne) и отдел (ManyToOne)
- пользователь имеет настройки уведомлений и интерфейса (OneToOne)
- пользователь имеет сессии, историю входов, уведомления, записи аудита (OneToMany)
- документ связан с типом, категорией, отделом, создателем (ManyToOne)
- документ связан с источником, OCR-результатом, классификацией (OneToOne)
- документ связан с файлами, AI-результатами, маршрутами, комментариями (OneToMany)
- документ связан с записями аудита и уведомлениями (OneToMany)

## Безопасность

JWT-токены с истечением срока. Все эндпоинты кроме /auth/login защищены AuthGuard. API-ключ AI-провайдера хранится в зашифрованном виде (AES-256-CBC). Роли пользователей (admin, operator) ограничивают доступ к административным функциям. Сессии отслеживаются, возможен принудительный выход.
